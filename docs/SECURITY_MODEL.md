# SentinelPulse Security Model

## 1. User Authentication and Authorization Flow

```text
User Request
     │
     ▼
Authentication (Session/Token)
     │
     ▼
Organization Membership Verification
     │
     ▼
Role-Based Access Control (RBAC: Admin / Viewer)
     │
     ▼
Authorized Resource Access
```

### 1.1 Authentication & RBAC
- Operators and administrators authenticate via secure session cookies or JWT access tokens issued by the canonical Go backend.
- Every authenticated user belongs to exactly one organization (`organization_id`), ensuring tenant isolation.
- Roles are strictly enforced as either `admin` (able to manage settings, generate enrollment tokens, acknowledge alerts, and execute commands) or `viewer` (read-only fleet overview and diagnostics).

---

## 2. Agent Enrollment and Trust Model

```text
Enrollment Token (One-time, Hashed)
     │
     ▼
One-Time Token Exchange via HTTPS
     │
     ▼
Endpoint Registration & Credential Issuance
     │
     ▼
Authenticated Telemetry & Heartbeat Push
     │
     ▼
Periodic Rotation & Revocation Support
     │
     ▼
Secure Local Storage (DPAPI-Protected SQLite Buffer)
```

### 2.1 Agent Enrollment
- Agents must present a valid, unexpired, unconsumed one-time enrollment token generated by an administrator.
- The server stores only the cryptographic hash of the enrollment token (`token_hash`) and consumes the token transactionally upon first use.
- Upon successful enrollment, the agent receives a persistent endpoint ID and device credential, stored locally using Windows Data Protection API (DPAPI).

## 3. Threat Mitigations and Security Controls

| Threat Vector | Potential Impact | Mitigation Control |
|---|---|---|
| **Tenant Escape** | Unauthorized cross-organization data access | Organization membership middleware, mandatory `organization_id` database predicates, and automated tenant-isolation integration tests. |
| **Stolen Enrollment Token** | Unauthorized endpoint registration | Cryptographic hashing (`token_hash`), one-time atomic consumption, short default expiration (24 hours), and revocation endpoints. |
| **Replayed Telemetry** | Stale or spoofed performance metrics | Monotonically increasing sequence numbers, event timestamps within a strict skew window, and idempotent ingestion handlers. |
| **Forged Agent / MitM** | Intercepted or fake telemetry | TLS 1.3 enforcement on all ingestion endpoints, endpoint credential validation, and optional client certificate pinning. |
| **Compromised Endpoint** | Agent secret extraction | Local configuration and offline buffer protected by Windows DPAPI tied to the LocalSystem service principal. |
| **Unauthorized Commands** | Remote code execution or disruptive actions | Role checks (`admin` only), command authorization records, explicit target endpoint validation, and immutable audit logging. |
| **SSE / Realtime Leakage** | Cross-tenant telemetry exposure | Authenticated WebSocket/SSE subscription handshake, server-side tenant derivation, and explicit channel filtering. |
| **Report Data Leakage** | Unauthorized export of fleet data | Tenant-scoped database queries, export rate limiting, administrator role check, and secure transient storage or streaming. |
| **Audit Bypass** | Untracked administrative changes | Append-only `audit_logs` table recording actor, tenant, action, target, outcome, IP address, and timestamp for all sensitive operations. |
